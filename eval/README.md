## D1 구성

- **변형**: `static`(내용이 HTML에 있음), `delayed`(base64로 감춘 내용을 1.2~2초 뒤 스크립트가 그림 — 정적 검사로는 안 보임), `redirect`(3단계 HTTP 리다이렉트 뒤 도착), `jsnav`(스크립트로 다른 페이지로 이동). 계열 A·B는 4변형, 나머지는 3변형.
- **정답이 URL에 드러나지 않게** 파일 이름은 의미 없는 ID(`/d1/p<해시>.html`)다. 규칙·모델은 URL 경로를 보지 않는다.
- **가상 브랜드만** 쓴다. 폼은 전송되지 않는다.
- 정상 대조는 로그인·결제·환급 안내·배송 조회·합법 체육진흥투표권 안내·피싱 주의 기사·후원 계좌·게임 캐시 충전처럼 의심 유형과 헷갈리는 화면이다.

## 개발용/평가용 분할

| | 개발용(dev) | 평가용(eval) |
|---|---|---|
| 피싱·사기·도박 | 유형마다 계열 A·C·E (10개씩) | 계열 B·D·F (10개씩) |
| 정상 대조 | 계열 A·C·E·G·I (15개) | 계열 B·D·F·H·J (15개) |

- 같은 계열의 변형은 한쪽에만 있다(템플릿을 외워서 맞히는 것을 막음).
- 정상 페이지 개발용은 D1·D3를 합쳐 30개로 둔다(기획서). D3가 들어오면 D1 개발용 15 + D3 개발용 15, 나머지 D3는 평가용.
- **평가용은 규칙·모델·프롬프트를 고정한 뒤 한 번만 연다.** `run.py`는 `--split eval`에 `--frozen-evaluation`을 요구하고, 작업 트리가 깨끗해야 실행하며, 먼저 고정 기록(`results/<실행>-freeze.json`: 커밋·AI 모델)을 남긴다.
- 한계: 개발용과 평가용 템플릿을 같은 개발자가 같은 시기에 썼다. 규칙(rules/1)은 D1보다 먼저(시험 페이지 7개 기준) 만들어졌고, 평가용 결과를 보고 규칙을 고치지 않는다. 고치면 새 버전으로 다시 고정하고 이전 결과와 함께 보고한다.

## 실행

```bash
python eval/generate.py                       # D1 페이지·목록 다시 만들기(시드 고정, 같은 결과)
docker compose restart testsites              # nginx 설정(리다이렉트·D2 경로) 반영

# 조사자 계정(예: eval-runner)을 CLI로 만든 뒤
EVAL_USER=eval-runner EVAL_PASSWORD=... python eval/run.py d2              # 공격 시나리오 15종
EVAL_USER=eval-runner EVAL_PASSWORD=... python eval/run.py d1 --split dev  # 개발용 45개
# 모델 비교: AI_MODEL=laya docker compose --profile laya up -d  후 같은 명령에 --tag laya
```

- D2-14(XSS)의 콘솔 확인은 Playwright가 있으면 콘솔에서 사건 상세를 열어 대화상자가 뜨는지 본다(`worker/.venv`로 실행).
- 결과는 `results/`에 JSON으로 남는다. 모든 비율은 건수와 95% Wilson 신뢰구간으로 낸다(`metrics.py`).
